# VVP → REDnote / Xiaohongshu: автоматическая публикация (экспериментальный адаптер)

**Статус 10.11.2026:** подготовка в отдельной ветке GitHub. **НЕ подключён, НЕ запущен, НЕ прошёл end-to-end тест с аккаунтом VVP.** Нельзя называть работающим автоматическим каналом до проверки и подтверждения публикации реального тестового материала.

## Цель

После восстановления инфраструктуры Beget сделать REDnote дополнительной **полностью автоматической веткой существующей дистрибуции**: WordPress → проверенная версия WPML zh-hans → фильтр пригодных публикаций → китайская адаптация/карточки → существующая очередь Make → REDnote worker (Playwright через обычный веб-интерфейс автора) → проверка статуса и ссылка → журнал публикаций. **Без ручного копирования и подтверждения каждой публикации.**

## Проверенные ограничения

- В документации OpenAccount scope `write_notes` отмечен как «规划中», а не как общедоступный API публикации: https://openaccount.xiaohongshu.com/docs/scope
- Sharing SDK сообщает `暂停接入`, публикация идёт через мобильное приложение: https://agora.xiaohongshu.com/
- Есть MIT-проект PostFlow с Playwright-автопубликацией (видео, браузер): https://github.com/jefftko/PostFlow. Использование сторонней автоматизации может противоречить условиям платформы, ломаться после изменений интерфейса и приводить к проверке/блокировке.
- Клиентский аккаунт ВВП в REDnote: ID `18771732643`; не верифицирован корпоративно; региональное ограничение 10.11.2026 снято самостоятельно. Тест сайта/публикации на VPS пока не выполнен.

## Варианты и решение

1. **Предпочтительно:** официальный доступ к записи материалов, если платформа его предоставит ВВП. Сейчас подтверждения нет.
2. **Эксперимент:** браузерный робот Playwright через UI creator.xiaohongshu.com. После одноразового входа хранит закрытую сессию на сервере и отправляет материалы автоматически. **Истечение сессии, CAPTCHA/2FA и изменения интерфейса не гарантируют работу без участия человека.** Никаких обходов антибот-защиты и чужих номеров.
3. Пока не доказана устойчивая работа — **канал не включать в боевую маршрутизацию**. Никаких ручных операций как постоянной части конвейера.

## Технический контракт задания

JSON передаётся через защищённый SSH/очередь, **не через публичный endpoint**:

```json
{
  "job_id": "vvp:wp:98765:zh-hans:rednote:v1",
  "wp_post_id": 98765,
  "language": "zh-hans",
  "title": "示例标题",
  "body": "示例正文",
  "tags": ["中俄合作", "俄罗斯"],
  "media_type": "images",
  "media_paths": ["/srv/vvp-media/rednote/inbox/98765/cover.png"]
}
```

Видео: `media_type="video"`, один путь MP4. Для реальной загрузки файлы должны быть уже получены из доверенных источников и лежать локально на сервере; никакие произвольные URL не скачиваются.

`job_id` стабилен для одного материала и версии. Применяется уникальный ключ в SQLite; ошибки до отправки можно переисполнить по правилам, а сомнительный результат после нажатия «Опубликовать» **не переотправлять слепо** во избежание дублей.

## Критерии готовности

- Подключение именно к **китайской версии WordPress** после завершённого WPML-перевода, изображения и проверки;
- две успешные публикации в тестовой среде: фото + видео; проверены публичные ссылки;
- автоматический мониторинг статуса, застреваний, CAPTCHA и авторизации;
- защита от повторной отправки при ошибке сети после нажатия Publish;
- ни одна поломка REDnote не задерживает WeChat, VK, Telegram и другие каналы;
- одна очередь и единая аналитика с каналом `rednote`, журнал `job_id/post_url` и возможностью отключения;
- отсутствие любых логинов, cookie, токенов и документов в GitHub.

## Следующие действия после восстановления VPS

1. В изолированной среде проверить доступ к `creator.xiaohongshu.com` и реальный DOM формы. Обновить селекторы из `worker.py`; никаких действий на боевом аккаунте до проверки.
2. Один раз авторизовать браузерный профиль на сервере (сессия может потребовать QR); убедиться в сохранении/изоляции данных.
3. Запустить `--inspect` (без отправки), затем реальный одиночный тест с проверкой публикации.
4. Провести штатный и аварийный тест (таймаут после нажатия) без повторного размещения.
5. Только после этого подключить маршрутизатор существующего Make-сценария и включить ограниченный объём публикаций.

Сейчас работа сайта/VPS недоступна, поэтому пункты 1–5 **не выполнены**.
